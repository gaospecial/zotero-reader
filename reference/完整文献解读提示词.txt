## 1. 产品定义

Zotero Reader 是面向已经使用 Zotero 的研究人员的 macOS 与 Windows 桌面应用。它借助 doc2x 服务把 Zotero 文献库中的论文自动解析为 Markdown，并调用多模态 DeepSeek 根据生成结构化中文解读。用户主要通过 AI 解读快速理解论文，而不是在应用内通读 PDF 或 Markdown。

产品以“单篇文献”为阅读、提问、批注与解读历史的基本单位。Zotero 是文献来源，AI 工作流提供用户内容，应用本地 SQLite 与文件目录是研究资料的权威副本。

核心目标：

- 把“从 Zotero 找到论文”到“读完可用的结构化解读”变成几乎无需配置的自动流程。
- 让 AI 结论可追溯、可与模型推断区分，并可在需要时回到 Markdown 章节或 Zotero PDF。
- 让文献、解读、问答和笔记保存在本地，并具备未来云同步所需的稳定数据模型。

## 2. 核心用户

核心用户是已经使用 Zotero 管理文献并开展研究工作的人员。

- 不预设学科。
- 不面向没有 Zotero 使用习惯的普通 PDF 读者。
- 不面向团队，不提供共享文库或多人协作。
- 不提供跨设备云同步，但数据模型必须为未来同步保留稳定 ID、版本和删除标记。

## 3. MVP 范围

MVP 必须跑通以下闭环：

1. 连接本机运行的 Zotero 桌面端。
2. 展示 Zotero 分类树，选择任意一个或多个分类。
3. 父分类默认递归包含子分类，并导入范围内全部顶层条目。
4. 对有主 PDF 的条目自动调用 Doc2X。
5. 自动生成中文标题翻译、一句话结论与提示词大纲规定的结构化解读。
6. 在解读阅读页查看解读内容与论文图片。
7. 针对单篇文献持续问答。
8. 在本地资源库做关键词检索、筛选、排序和阅读状态管理。
9. 将文献移入应用回收站，并显式批量同步到 Zotero 回收站。
10. 导出与恢复本地备份。

MVP 明确不包含：

- 相关文献推荐；
- 同方法文献检索；
- 语义检索；
- 文献综述；
- 跨文献问答；
- 云同步、共享文库、团队协作；
- 应用内 PDF 或 Markdown 全文阅读器；
- Word/PDF/图片卡片导出；
- 直接发布到社交媒体；
- 应用内自动更新；
- Mac App Store 或 Microsoft Store 分发；
- 应用级数据库或文件加密。

相关文献、同方法检索和文献综述可以在后续版本实现，但不能扩大当前 MVP 的实现范围。

## 4. 核心用户旅程

### 4.1 首次使用

1. 应用检测 `http://127.0.0.1:23119/api/users/0/`。
2. 连接成功后加载 Zotero 分类树。
3. 用户选择一个或多个分类。

### 4.2 导入与自动处理

1. 导入前预览分类范围、条目总数、含 PDF 数量与无 PDF 数量。
2. 导入所选分类中有 PDF 的文献进入异步 Doc2X 解析队列。
3. 解析成功后立即进入自动 AI 解读队列。
4. 无 PDF 的条目跳过。
5. 解析和生成过程保持静默。

### 4.3 阅读（参见figma的主界面）

1. 应用仿照Google Reader，有两种视图，默认进入紧凑视图，显示文献列表。
2. 列表主文字为中文翻译标题，第二行为一句话结论。
3. 阅读视图展示提示词大纲规定的结构化章节与论文图片轮播。

### 4.4 提问与笔记

1. 在右侧问答面板围绕当前文献提问。
2. 问答使用流式输出，完成后显示来源、图片引用、视觉分析/模型推断标识与用量。
3. 通过“备忘”按钮打开弹窗编辑该文献唯一的总笔记。

### 4.5 回收

1. 用户移除文献时，本地文献立即进入应用回收站。
2. 用户在应用回收站显式执行“同步到 Zotero 回收站”，统一申请 Zotero 写授权并批量处理。

## 5. 功能规格

### 5.1 Zotero 连接

首期唯一文献来源是本机 Zotero 桌面端本地 HTTP API，不允许直接读 `zotero.sqlite`。

已验证环境：

- 基础地址：`http://127.0.0.1:23119/api/users/0`
- Zotero API v3
- 分类和条目支持 `limit`、`start` 分页
- 响应包含 `Total-Results`、`Last-Modified-Version` 等版本头
- 附件可通过 item key 的 `/file` 端点读取
- 写请求需要先通过 `POST /api/local/authorize` 获得本地授权

实现要求：

- Rust 侧调用 Zotero 本地 API，不使用 Web API、Zotero 账户密钥或用户填写的 Library ID/API Key。
- 分页读取分类、分类关系、顶层条目、附件和回收站状态。
- API 不可用、端口不通、权限不足时显示明确连接错误，不降级为数据库读取。
- 应用启动和重新连接后自动执行只读增量同步。
- 顶栏保留“同步 Zotero”按钮用于立即刷新。
- 同步必须幂等，不产生重复文献、分类或笔记。
- Zotero 拥有的元数据以 Zotero 为权威；应用自有 AI 结果、笔记和阅读状态不被重新导入覆盖。
- Zotero 写授权保存在系统钥匙串，有效期内复用；实际写请求仍需用户明确确认。

### 5.2 分类与导入

- “文件夹”统一称为“Zotero 分类”。
- 选择父分类时递归包含全部子分类。
- 导入所选分类中的全部顶层条目，不筛选掉无 PDF 条目。
- 一篇文献记录对应一个 Zotero 顶层条目或无父条目的独立 PDF。
- 子 PDF、子笔记与附件归属于父文献，不重复生成顶层文献。
- 一个条目只有一个主 PDF。只有一个 PDF 时自动采用；多个 PDF 时只在该条目的导入流程中要求选择主 PDF。
- 再次导入同一分类采用非破坏式更新：
  - 新增新条目；
  - 更新 Zotero 元数据和分类关系；
  - 保留本地 Markdown 版本、解读历史、问答和笔记；
  - 移出分类只解除分类关系，不自动删除本地记录。
- 导入任务应支持暂停/继续或至少支持取消尚未开始的项目。

### 5.3 PDF 与 Doc2X

- PDF 原文件留在 Zotero 原位置，应用不复制 PDF。
- PDF 不可被应用修改。
- 有可用主 PDF 的文献在导入后自动进入 Doc2X 异步解析。
- 无 PDF 的文献跳过解析，标记为“仅元数据”，仍自动生成初步解读。
- PDF 在导入后被移动、重命名或删除时：
  - 已生成的 Markdown、解读、问答和笔记继续可用；
  - PDF 标记“来源不可用”；
  - 提供重新关联或重新同步入口。

文档状态应拆成独立维度，而不是一个互相覆盖的枚举：

- `pdf_state`: `available | missing | unavailable`
- `parse_state`: `not_started | queued | processing | retry_wait | succeeded | failed`
- `ai_state`: `not_started | queued | generating | vision_wait | succeeded | failed`
- `zotero_state`: `active | trashed | missing`
- `local_state`: `active | trashed | permanently_deleted`

解析要求：

- 使用 Doc2X v2 预上传、上传、轮询状态和拉取结果流程。
- Doc2X 成功结果是一个 ZIP 文件，至少包含 Markdown 与 `figures/`；表格和公式可内嵌在 Markdown 中。
- 解析成功后，Doc2X 提供短期 ZIP 下载链接。桌面端直接从该链接下载。
- 桌面端下载前校验 URL 为 HTTPS 且域名在服务端下发的可信下载域名白名单内；不得跟随跨白名单重定向。
- 桌面端先下载 ZIP 到临时目录，校验大小与哈希，防止 Zip Slip 路径穿越和解压炸弹，再原子解压到该论文的解析版本文录；成功后写入 SQLite。
- 成功时保持静默。瞬时错误自动重试有限次数；最终失败在文献与导入批次中显示，原因可展开并支持手动重试。
- 每次重新解析生成新的 Markdown 版本，不覆盖旧版本。

### 5.4 Markdown、图片与来源

- Markdown 是 AI 输入和引用定位依据，不在主阅读区展示。
- Markdown 只读，用户纠错通过笔记表达。
- 论文内有效图表完整保留，排除页眉、页脚、期刊徽标和装饰元素。
- 图片、表格和公式都归属于具体 Markdown 版本。
- 图片按原文顺序形成阅读页轮播，显示图号、标题与来源入口。
- 来源弹窗只显示被引用的 Markdown 章节和必要上下文，不加载整篇 Markdown。
- “查看 PDF”跳回 Zotero，应用不内置 PDF 全文查看器。


### 5.6 全文问答

- 每篇文献只有一个持久问答会话，不跨文献混合上下文。
- 问答默认只使用当前文献的 Markdown 原文，不自动加入用户笔记。
- 主动问答使用 SSE 流式传输。
- 流式事件至少区分：文本增量、来源、视觉引用、模型推断、错误、用量与结束。
- 回答必须引用 Markdown 章节；内容不存在时直接说明“文献未提及”，不得编造。
- 需要视觉信息时，使用与解读相同的按需图片流程。
- 用户可确认后“清空当前会话”；清空后仍是一篇文献一个会话，不影响文献、解读、笔记或其他历史。

### 5.7 笔记

- 笔记属于对应文献，可编辑、删除，并进入本地搜索。
- 重新生成 AI 解读不迁移或复制旧笔记；旧笔记留在所属解读版本。
- 重新解析 Markdown 创建新版本；旧 Markdown 与相关笔记保留，AI 历史继续引用原版本。
- “查看备忘”页面汇总所有定位笔记和总笔记，支持搜索、更新时间排序、编辑并跳回文献与定位位置。

### 5.8 回收站与 Zotero 同步

- 应用有自己的回收站。
- 用户点击“移除”后，文献立即从主资源库移入应用回收站。
- 应用回收站提供明确的“同步到 Zotero 回收站”按钮并显示待同步数量。
